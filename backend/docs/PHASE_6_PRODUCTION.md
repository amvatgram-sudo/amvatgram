# Phase 6 — Production, E2E and Deployment

## Added
- PostgreSQL migration command: `npm run db:migrate`
- Production readiness check: `npm run production:check`
- API smoke test: `npm run test:smoke`
- Docker image for API and multi-stage frontend image
- PostgreSQL + API + Nginx compose stack
- Nginx SPA fallback and `/api` reverse proxy
- Health checks and graceful API shutdown
- Bounded in-memory rate limiter to prevent unbounded key growth
- Transactional payment verification/webhook + subscription activation
- Frame-payment one-time consumption to prevent reuse on multiple ads
- Database connection timeout/statement timeout/pool controls
- 404 API response with request ID

## Local
1. Copy `.env.example` and configure PostgreSQL.
2. `npm install`
3. `npm run db:migrate`
4. `npm run server`
5. In another terminal: `npm run dev`
6. `npm run test:smoke`

## Production with Docker
1. Copy `.env.production.example` to `.env` and replace every placeholder.
2. Set `CORS_ORIGIN` and `PAYMENT_RETURN_URL` to the real HTTPS domain.
3. Configure a real OTP provider and real payment gateway adapter/webhook.
4. Run: `docker compose up -d --build`
5. Verify: `curl https://YOUR_DOMAIN/health`
6. Review logs and run `npm run security:audit` before release.

## Important operational requirements
- The current rate limiter is process-local. A multi-replica deployment must move rate limiting to Redis or another shared store.
- Payment success is never generated by the browser. The gateway webhook or authorized manual verification is authoritative.
- Payment and subscription state changes are transactional.
- TLS termination should be handled by a trusted reverse proxy/load balancer in front of the web container.
- Do not commit `.env`, production secrets, payment credentials, OTP credentials, or admin password hashes.

## Locations
- Persistent locations now have a PostgreSQL table and RBAC-protected create endpoint.
- Public reads come from the API when available; the existing bundled locations remain a safe fallback for offline/first-run UX.
- Temporary user-selected ceremony locations may remain client-local; permanent catalog changes require `LOCATION_MANAGE`.
