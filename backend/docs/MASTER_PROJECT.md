# MASTER PROJECT — Amvatgram
## مرجع جامع، مهندسی و اجرایی پروژه امواتگرام

**نام پروژه:** Amvatgram / امواتگرام  
**نوع محصول:** سامانه وب و موبایل ثبت و اطلاع‌رسانی آگهی ترحیم و مراسم  
**نسخه مبنا:** MVP / Version 1  
**محدوده جغرافیایی شروع:** مریوان (قابل توسعه به کل کشور)  
**پلتفرم هدف:** Web (React + Vite + Tailwind) + Backend API + Mobile View / PWA  
**وضعیت نقشه:** این سند مرجع رسمی و استخوان‌بندی تصمیم‌گیری پروژه است.

---

### ۱. تفکیک حالت‌های همکاری (آموزشی vs اجرایی)
برای بهینه‌سازی سرعت و عمق یادگیری، دو حالت کاری معین شده است:
1. **حالت آموزشی (Mentorship Mode):** هنگامی که با مفاهیم پایه‌ای، معماری، احراز هویت، جریان‌های پیچیده و دیتابیس روبه‌رو می‌شویم.
2. **حالت اجرایی (Sprint/Delivery Mode):** برای کارهای روتین و پیاده‌سازی فرم‌ها یا استایل‌های تکراری با تمرکز بر تحویل سریع و باکیفیت.

---

### ۲. فازبندی کلان نقشه راه (Roadmap)
- **Phase 0:** زیرساخت، ساختار فایل‌ها، تعاریف تایپ‌ها و مستندسازی کنترلی
- **Phase 1:** احراز هویت (OTP، تفکیک مذهب شیعه/سنی، نقش کاربر و صاحب عزا)
- **Phase 2:** مدیریت آگهی‌های ترحیم، متوفی، مراسم و جریان تأیید (Draft/Pending/Approved/Archived)
- **Phase 3:** رابط کاربری وب (صفحه اصلی، کارت‌ها، جزئیات، فیلترها، جستجو)
- **Phase 4:** مسیریابی مراسم (Google Maps, Waze, Neshan, Apple Maps با مختصات دقیق)
- **Phase 5:** تسلیت، کامنت، واکنش قلب مشکی، قالب‌های آماده بر اساس مذهب و زبان
- **Phase 6:** تولید خودکار اعلامیه ترحیم با قالب گرافیکی محترمانه
- **Phase 7:** پنل مدیریت، تایید و رد آگهی، مدیریت مساجد و آرامستان‌های مریوان
- **Phase 8:** آرشیو هوشمند خودکار (۷ روز پس از مراسم) و اشتراک‌گذاری اجتماعی
- **Phase 9:** امنیت، گزارش‌گیری و بهینه‌سازی نهایی

---

### ۳. قوانین الزامی و حیاتی
- هر تغییر باید در قالب یک Task مشخص باشد.
- هیچ فازی بدون گذراندن Acceptance Criteria و اعتبارسنجی تایید نمی‌شود.
- دیتابیس و اعتبارسنجی‌ها برای احترام به حریم خصوصی و شأن متوفی به صورت سفت‌وسخت کنترل می‌شوند.
